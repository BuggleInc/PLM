The HTTP protocol

The HTTP server of this world, named plm-httpd/1.0, serves static files in HTTP/1.1 (RFC 9112) as the usual servers. The client sends a request naming a file, and the server answers with a response holding its content.

Framing

A request starts with a line giving the method, the path of the file and the version of the protocol, such as GET /index.html HTTP/1.1. Header lines of the form Name: value follow, then an empty line ending the request. Each line ends with the two bytes \r\n (CR and LF, 13 and 10), but the server also accepts \n alone. The names of the headers are case-insensitive. A request may have a body, whose size in bytes is given by its Content-Length header, after the empty line.

A response has the same structure: a status line (such as HTTP/1.1 200 OK), header lines and an empty line, all ended by \r\n, then the body: the content of the file, or a small HTML page describing the error. The headers of the response are always the same, in this order:

Server: plm-httpd/1.0The name of the server.
Date: Mon, 01 Jan 2024 00:00:00 GMTThe date of the response. The clock of the world starts on January 1st, 2024 at midnight.
Content-Type: text/plaintext/html for the files whose name ends with .html and for the error pages, text/plain for the other files.
Content-Length: 14The size of the body in bytes.
Allow: GET, HEADThe methods that the server accepts, only in the 405 responses.
Connection: keep-alivekeep-alive if the server waits for another request on the connection, close if it closes the connection after the response.

The body of the response is not followed by any marker: the client knows where it ends from Content-Length, or from the end of the stream when the server closes the connection after the response.

Requests

The server accepts two methods: GET asks for the file, and HEAD asks for the same response without its body (with the Content-Length that the body would have). The path designates a file of the server, without directory listing nor index page: / alone is not found. What follows a ? in the path is ignored.

The server accepts the versions HTTP/1.1 and HTTP/1.0, and always answers in HTTP/1.1. In HTTP/1.1, the request must have a Host header, giving the name or the address of the server (such as Host: 10.0.0.1). The connection persists after the response: the server waits for the next request on the same connection, unless the request has the header Connection: close. In HTTP/1.0, the server closes the connection after the response, unless the request has the header Connection: keep-alive.

Status codes

200 OKThe body is the content of the file.
400 Bad RequestThe request is malformed (its first line is not made of three words separated by single spaces, its path does not start with /, its version does not start with HTTP/, or its Content-Length is not a number), or it lacks the Host header in HTTP/1.1. The server closes the connection after the response.
404 Not FoundThe file does not exist.
405 Not AllowedThe method is neither GET nor HEAD.
505 HTTP Version Not SupportedThe version is neither HTTP/1.1 nor HTTP/1.0. The server closes the connection after the response.

Example session

In this session, the server holds the file /doc/hello.txt, containing the line Hello, world! (14 bytes with its \n). The client asks for it, then asks on the same connection for the headers of a missing file, and for the closing of the connection. The lines starting with C: are sent by the client, and those starting with S: by the server. These prefixes are not part of the data, and \r and \n stand for the bytes CR and LF.

C: GET /doc/hello.txt HTTP/1.1\r\n
C: Host: 10.0.0.1\r\n
C: \r\n
S: HTTP/1.1 200 OK\r\n
S: Server: plm-httpd/1.0\r\n
S: Date: Mon, 01 Jan 2024 00:00:00 GMT\r\n
S: Content-Type: text/plain\r\n
S: Content-Length: 14\r\n
S: Connection: keep-alive\r\n
S: \r\n
S: Hello, world!\n
C: HEAD /missing.html HTTP/1.1\r\n
C: Host: 10.0.0.1\r\n
C: Connection: close\r\n
C: \r\n
S: HTTP/1.1 404 Not Found\r\n
S: Server: plm-httpd/1.0\r\n
S: Date: Mon, 01 Jan 2024 00:00:00 GMT\r\n
S: Content-Type: text/html\r\n
S: Content-Length: 154\r\n
S: Connection: close\r\n
S: \r\n

The server then closes the connection.
