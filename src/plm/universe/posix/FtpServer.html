The FTP protocol

The FTP server of this world, named plm-ftpd 1.0, serves files in passive mode (RFC 959) as the usual servers. The client sends its commands on a first connection, called the control connection, and each file or listing comes on a connection of its own, called a data connection, which the client opens on a port given by the server.

Framing

On the control connection, each command is a line ended by the two bytes \r\n (CR and LF, 13 and 10), made of a word followed by an argument, such as CWD pub. The server also accepts \n alone, and the commands are case-insensitive. Each reply of the server starts with a code of three digits, followed by a space and a text, such as 230 Login successful., and ends with \r\n. The first digit of the code tells the kind of reply: 1 for a preliminary reply (another reply follows when the action completes), 2 for a success, 3 when the server waits for another command, 4 and 5 for an error.

A reply may span several lines: its first lines start with the code followed by a dash (220-), and its last line with the code followed by a space (220 ). The client must read the lines until the one with a space after the code. Only the welcome of the server spans several lines, whose first ones may change from one world to another.

On a data connection, the server sends the data as it is, without any marker: the end of the data is the end of the stream, when the server closes the data connection.

Commands

USER anonymousStarts the login. The server only accepts the anonymous users, named anonymous or ftp, and answers 331 Please specify the password.
PASS passwordEnds the login, with any password (usually an email address), answered by 230 Login successful.
SYSTAsks for the system of the server: 215 UNIX Type: L8
TYPE I or TYPE ASwitches to the binary or the ASCII mode: 200 Switching to Binary mode. or 200 Switching to ASCII mode. The data is sent unchanged in both modes.
PWDAsks for the current directory: 257 "/pub" is the current directory
CWD directoryChanges the current directory: 250 Directory successfully changed.
PASVPrepares a data connection: the server answers 227 Entering Passive Mode (h1,h2,h3,h4,p1,p2). The client then connects to the address h1.h2.h3.h4, on the port p1*256+p2.
EPSVPrepares a data connection as PASV, giving only the port: 229 Entering Extended Passive Mode (|||port|)
RETR fileSends the file on the data connection.
LIST directorySends the content of the directory (by default the current one) on the data connection, one line per entry in the format of ls -l, ended by \r\n (see the example below).
QUITEnds the session: the server answers 221 Goodbye. and closes the connection.

The paths are relative to the current directory, unless they start with /, and .. designates the parent directory. The current directory is / after the login.

Transfers

Each transfer needs a new data connection: the client sends PASV (or EPSV), connects a new socket to the given port, which changes at each PASV, and sends RETR or LIST, before or after connecting. The server then answers a preliminary reply on the control connection, sends the data on the data connection and closes it, and confirms the end of the transfer on the control connection: 150 Opening ASCII mode data connection for file (size bytes). (or BINARY) then 226 Transfer complete. for RETR, 150 Here comes the directory listing. then 226 Directory send OK. for LIST.

Errors

The errors do not close the connection.

425 Use PORT or PASV first.RETR or LIST without a data connection prepared by PASV or EPSV.
500 Unknown command.The command does not exist.
500 Unrecognised TYPE command.Another type than I or A.
503 Login with USER first.PASS before USER.
530 Please login with USER and PASS.A command that needs the client to be logged in.
530 This FTP server is anonymous only.USER with another name than anonymous or ftp.
550 Failed to open file.RETR of a missing file.
550 Failed to change directory.CWD to a missing directory.

Example session

In this session, the server 10.0.0.1 holds the file /pub/hello.txt, containing the line Hello, world! (14 bytes with its \n). The lines starting with C: are sent by the client on the control connection, those starting with S: by the server on the control connection, and those starting with D: by the server on the data connection. These prefixes are not part of the data, and \r and \n stand for the bytes CR and LF.

S: 220-Welcome to the BuggleInc FTP server.\r\n
S: 220 plm-ftpd 1.0 ready.\r\n
C: USER anonymous\r\n
S: 331 Please specify the password.\r\n
C: PASS buggle@\r\n
S: 230 Login successful.\r\n
C: CWD pub\r\n
S: 250 Directory successfully changed.\r\n
C: PASV\r\n
S: 227 Entering Passive Mode (10,0,0,1,156,64).\r\n
C: RETR hello.txt\r\n
S: 150 Opening ASCII mode data connection for hello.txt (14 bytes).\r\n
D: Hello, world!\n
S: 226 Transfer complete.\r\n
C: PASV\r\n
S: 227 Entering Passive Mode (10,0,0,1,156,65).\r\n
C: LIST\r\n
S: 150 Here comes the directory listing.\r\n
D: -rw-r--r--    1 ftp      ftp            14 Jan 01  2024 hello.txt\r\n
S: 226 Directory send OK.\r\n
C: QUIT\r\n
S: 221 Goodbye.\r\n

After each reply to PASV, the client connects a new socket to 10.0.0.1, on the port 156*256+64 = 40000 for the file, then 156*256+65 = 40001 for the listing. The server closes each data connection after sending its data, and the control connection after its reply to QUIT.
