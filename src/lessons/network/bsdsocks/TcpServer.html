Serving a client

This time, your program is the server: write the function server(port), where a client will connect to the given port of your machine, send a line of text ended by '\n', and wait for your answer before closing the connection. Your mission is to be a doubling echo: you must send the received line twice to the client, with its '\n' each time.

A server takes more steps than a client, since it must first prepare a socket that waits for the connections:

  1. Create a socket with socket(AF_INET, SOCK_STREAM, 0).
  2. Attach it to the given port with bind(). The struct sockaddr_in is filled as for connect(), but the address INADDR_ANY (converted with htonl()) means that any machine may connect.
  3. Mark it as accepting the connections with listen(). Its second parameter is the length of the queue of the clients that wait to be accepted. After this call, the clients can connect even if your program does not accept and serve them yet.
  4. Accept a client with accept(), which waits until a client connected and returns a new descriptor, dedicated to this client. You can pass NULL as second and third parameters if the address of the client does not matter.
  5. Receive the line on the new descriptor with recv(). As in the previous exercise, the line may arrive in several packets, so a single recv() may only return its beginning: keep receiving until you got its '\n'. You cannot wait for the end of the stream instead, since the client waits for your answer before closing the connection. Marking where a message ends, as this '\n' does, is called framing.
  6. Send the line twice to the client with send().
  7. Close both descriptors: the one of the client, and the one that waits for the connections.

Look at the world view while your program runs: the socket returned by accept() shares its port with the socket that waits for the connections. A port is not a socket on which external connections plug: the system dispatches the incoming data to the right application depending on four pieces of information: {source IP, source port, destination IP, destination port}. The destination IP is used to find the right machine, and then the operating system of that machine delivers the data using the three other pieces of information, not only the destination port. Doing otherwise would not be convenient for servers serving many incoming connections, as the number of available ports is limited to 65535 on a given machine. If each incoming connection were given a specific port, large servers would quickly run out of available ports. Indeed, it is not possible to have more than 65535 ports on a given machine, because the port number is encoded as a 16 bit integer on the Internet.
