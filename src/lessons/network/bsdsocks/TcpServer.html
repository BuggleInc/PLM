Serving a client

This time, your program is the server: write the function server(port, message), where a client will connect to the given port of your machine and wait for a message. Send it the given message, and close the connection: the client reads until the end of the stream, as your client did in the previous exercise. As in that exercise, the port and the message change from one world to the other.

A server takes more steps than a client, since it must first prepare a socket that waits for the connections:

    [!c|python]
  1. Create a socket with [!c]socket(AF_INET, SOCK_STREAM, 0)[/!][!python]socket.socket(socket.AF_INET, socket.SOCK_STREAM)[/!].
  2. Attach it to the given port with bind(). [!c]The struct sockaddr_in is filled as for connect(), but the address INADDR_ANY (converted with htonl()) means that any machine may connect.[/!][!python]Its address is the tuple ("", port), where the empty host means that any machine may connect.[/!]
  3. Mark it as accepting the connections with listen(). Its [!c]second[/!][!python]only[/!] parameter is the length of the queue of the clients that wait to be accepted. After this call, the clients can connect even if your program does not accept and serve them yet.
    4. [/!] [!java|scala]
  4. Create a socket that waits for the connections with new ServerSocket(port). This constructor does the first three steps of a server at once: it creates a TCP socket, attaches it to the given port with bind() so that any machine may connect, and marks it as accepting the connections with listen(). After that, the clients can connect even if your program does not accept and serve them yet. To do these steps one by one, create the ServerSocket without parameter, and call its method bind(new InetSocketAddress(port), backlog), whose second parameter is the length of the queue of the clients that wait to be accepted.
    5. [/!]
  5. Accept a client with accept(), which waits until a client connected and returns a new [!c]descriptor, dedicated to this client. You can pass NULL as second and third parameters if the address of the client does not matter.[/!][!python]socket, dedicated to this client, along with the address of the client.[/!][!java|scala] Socket, dedicated to this client.[/!]
  6. Send the message to the client on the new [!c]descriptor with send(), whose length is given by strlen(message)[/!][!python]socket with sendall(), which sends all the data. It sends bytes: convert the message with message.encode()[/!][!java|scala]socket with the write() method of its getOutputStream[!java]()[/!], which sends all the data. It sends bytes: convert the message with message.getBytes(StandardCharsets.UTF_8)[/!].
  7. Close both [!c]descriptors[/!][!python|java|scala]sockets[/!]: the one of the client, and the one that waits for the connections.

Look at the world view while your program runs: the socket returned by accept() shares its port with the socket that waits for the connections. A port is not a socket on which external connections plug: the system dispatches the incoming data to the right application depending on four pieces of information: {source IP, source port, destination IP, destination port}. The destination IP is used to find the right machine, and then the operating system of that machine delivers the data using the three other pieces of information, not only the destination port. Doing otherwise would not be convenient for servers serving many incoming connections, as the number of available ports is limited to 65535 on a given machine. If each incoming connection were given a specific port, large servers would quickly run out of available ports. Indeed, it is not possible to have more than 65535 ports on a given machine, because the port number is encoded as a 16 bit integer on the Internet.
