Downloading a message

In this first exercise about networking, you shall write the function client(server, port), which connects using TCP to the given server (its IPv4 address as text, such as "10.0.0.1") on the given port, reads all the data sent by the server, and writes it on its standard output. Your code will be tested on several situations in which the server and the content of its message change, so your function must use its parameters, and display what it received, whatever it is. Use the combo box above the world view on the right to switch the world.

Here are the steps to follow in your code. You can find more information [!c|python]about the socket(), connect(), recv() and friends[/!] in [!c]the corresponding manpages[/!][!python]the documentation of the socket module of Python[/!][!java]the documentation of the classes Socket and InputStream of Java[/!].

    [!c|python]
  1. [!c]Create a socket with socket(AF_INET, SOCK_STREAM, 0), which returns a descriptor.[/!][!python]Import the socket module, and create a socket with socket.socket(socket.AF_INET, socket.SOCK_STREAM), which returns a socket object.[/!] AF_INET means that this socket can go to the internet while SOCK_STREAM means that you want to use a stream of data. Together, these parameters give a TCP socket.
  2. [!c]Fill a struct sockaddr_in with the address of the server. Do not forget that the port must be given in network byte order, with htons(), while inet_pton() converts the textual address.[/!][!python]The address of the server is simply the tuple (server, port): the socket module converts it for the system.[/!]
    3. [/!] [!java]
  3. Create a socket connected to the server with new Socket(server, port), which creates a TCP socket and connects it at once. In this exercise, the server is sometimes slow to start, making this constructor throw a ConnectException. When this happens, you should wait one second with Thread.sleep(1000) and try again. The constructor closes the socket of a failed attempt by itself.
    4. [/!] [!c|python]
  4. Connect your socket to the server with connect(). In this exercise, the server is sometimes slow to start, making connect() [!c]return -1 (with errno set to ECONNREFUSED)[/!][!python]raise a ConnectionRefusedError[/!]. When this happens, you should wait one second with [!python]time.[/!]sleep(1) and try again. Beware: after a failed connect(), the state of the socket is unspecified. To retry, close it and create a new one with socket(). Do not forget to close the sockets of the failed attempts, or they will remain open at the end of your program.
    5. [/!]
  5. Receive the message [!java]from the stream returned by getInputStream(), with read(buffer), which returns the amount of bytes received[/!][!c]in a buffer with recv(), which returns the amount of bytes received[/!][!python]with recv(512), which returns the bytes received (at most 512 here)[/!]. Beware that the message may be conveyed from the server to you in several packets. The [!c|python]function recv()[/!][!java]method read()[/!] returns the available data when there is some, and it's blocking when no data is available but more data could come from the network. Finally, it returns [!c]0[/!][!python]empty bytes (b"")[/!][!java]-1[/!] when no data is available and no more data could come because the other part (the server) closed the connection. So you should keep reading from the network until [!c|python]recv()[/!][!java]read()[/!] returns [!c]0[/!][!python]empty bytes[/!][!java]-1 (transferTo() does this loop for you, but write it once yourself)[/!].
  6. Write the received bytes on the standard output with [!c]write(), printf(), or similar[/!][!python]sys.stdout.buffer.write(), which writes bytes (print() writes text)[/!][!java] System.out.write(buffer, 0, received), which writes bytes (print() writes text)[/!]. If you receive the data in several chunks from [!c|python]recv()[/!][!java]read()[/!], you are free to display in one or several chunks, as you prefer.[!c] Beware: the data received from the network is not a C string, as nothing ends it with '\0', and it must never be used as the format of printf(), since an attacker could put conversions such as %s in it.[/!]
  7. Close your socket with close()[!python], or create it in a with block that closes it at its end[/!][!java], or create it in a try-with-resources block that closes it at its end[/!]: the PLM checks that your program leaves no descriptor open, except the 3 standard ones that are already open when your process starts.
[!c]

These functions return -1 when they fail, and set errno to the reason of the failure. When this happens, use perror() to display the error on the standard error. Checking the returned values is a good habit, which will help you understand what goes wrong (and it's needed to pass this exercise).

[/!] [!python]

These methods raise an OSError when they fail, whose subclass tells the reason of the failure (such as ConnectionRefusedError). Only catch the errors that you expect and know how to handle: the other ones stop your program, and the PLM console shows where.

[/!] [!java]

These methods throw an IOException when they fail, whose subclass tells the reason of the failure (such as ConnectException). Only catch the exceptions that you expect and know how to handle, and declare the other ones with throws: they stop your program, and the PLM console shows where.

[/!]

Your debugging messages also reach the standard output (or the standard error), where the world view shows them. Remove them once your program works, as the PLM compares everything your program writes.
