Downloading a message

In this first exercise about networking, you shall write the function client(server, port), which connects using TCP to the given server (its IPv4 address as text, such as "10.0.0.1") on the given port, reads all the data sent by the server, and writes it on its standard output. Your code will be tested on several situations in which the server and the content of its message change, so your function must use its parameters, and display what it received, whatever it is. Use the combo box above the world view on the right to switch the world.

Here are the steps to follow in your code. You can find more information about the socket(), connect(), recv() and friends in the corresponding manpages.

  1. Create a socket with socket(AF_INET, SOCK_STREAM, 0), which returns a descriptor. AF_INET means that this socket can go to the internet while SOCK_STREAM means that you want to use a stream of data. Together, these parameters give a TCP socket.
  2. Fill a struct sockaddr_in with the address of the server. Do not forget that the port must be given in network byte order, with htons(), while inet_pton() converts the textual address.
  3. Connect your socket to the server with connect(). In this exercise, the server is sometimes slow to start, making connect() return -1 (with errno set to ECONNREFUSED). When this happens, you should wait one second with sleep(1) and try again. Beware: after a failed connect(), the state of the socket is unspecified. To retry, close it and create a new one with socket(). Do not forget to close the sockets of the failed attempts, or they will remain open at the end of your program.
  4. Receive the message in a buffer with recv(), which returns the amount of bytes received. Beware that the message may be conveyed from the server to you in several packets. The function recv() returns the available data when there is some, and it's blocking when no data is available but more data could come from the network. Finally, it returns 0 when no data is available and no more data could come because the other part (the server) closed the connection. So you should keep reading from the network until recv() returns 0.
  5. Write the received bytes on the standard output with write(), printf(), or similar. If you receive the data in several chunks from recv(), you are free to display in one or several chunks, as you prefer. Beware: the data received from the network is not a C string, as nothing ends it with '\0', and it must never be used as the format of printf(), since an attacker could put conversions such as %s in it.
  6. Close your socket with close(): the PLM checks that your program leaves no descriptor open, except the 3 standard ones that are already open when your process starts.

These functions return -1 when they fail, and set errno to the reason of the failure. When this happens, use perror() to display the error on the standard error. Checking the returned values is a good habit, which will help you understand what goes wrong (and it's needed to pass this exercise).

Your debugging messages also reach the standard output (or the standard error), where the world view shows them. Remove them once your program works, as the PLM compares everything your program writes.
