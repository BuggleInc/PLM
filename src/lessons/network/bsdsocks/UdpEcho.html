UDP echo server

The DNS server said that the port 6666 of the XMPP server is a decoy, and that the real port would come by itself once a UDP echo server runs on the port 6666 of your own machine. An echo server is one of the oldest services of the Internet (RFC 862): it sends every datagram that it receives back to its sender, unchanged. Its clients use it to check that the network carries their data faithfully.

This time, your program is the server of the datagrams. There is no connection in UDP: a single socket receives the datagrams of all the clients, in the order they arrive, and answers each of them with the address given by [!c|python]recvfrom()[/!][!java|scala]receive()[/!]. The server cannot guess this address: each client sends from its own port, which its system picks for it.

[!c]

Here are the functions involved. Check the manpages for more info.

  1. int bind(int sockfd, const struct sockaddr *addr, socklen_t addrlen) attaches the socket to a port of your machine, as for a TCP server: the struct sockaddr_in holds the port (converted with htons() and stored in addr.sin_port) and the address INADDR_ANY (converted with htonl() and stored in addr.sin_addr.s_addr), meaning that any machine may send to it. A datagram sent to a port where no socket is bound is lost. As for TCP, set the address family to AF_INET.
  2. recvfrom() fills its src_addr with the address of the sender, and sendto() takes such an address as destination: you can give the one filled by recvfrom() as is.
  3. recvfrom() returns the number of bytes received. A datagram may contain any byte, so its data is not a string ended by a zero byte.
[/!] [!python]

Here are the methods involved. Check the documentation of the socket module for more info.

  1. sock.bind(("", port)) attaches the socket to a port of your machine, as for a TCP server: the empty host means that any machine may send to it. A datagram sent to a port where no socket is bound is lost.
  2. sock.recvfrom(bufsize) returns the data and the address of its sender, which sock.sendto(data, address) takes as is.
  3. The re module finds patterns in a text, or in bytes: re.search(rb"...", data) returns the first match of the pattern in the bytes, or None.
[/!] [!java|scala]

Here are the classes and methods involved[!scala], from Java[/!]. Check their documentation for more info.

  1. new DatagramSocket(port) creates a UDP socket attached to that port of your machine, as for a TCP server: any machine may send to it. A datagram sent to a port where no socket is bound is lost.
  2. After socket.receive(packet), the packet holds the address of the sender: packet.getSocketAddress(). new DatagramPacket(byte[] buf, int length, SocketAddress address) prepares a datagram to send to such an address.
  3. The data of a received packet is in its array, from 0 to packet.getLength() (the rest of the array is what it held before): new String(array, 0, length, StandardCharsets.US_ASCII) gives its text. Pattern.compile("...") and its method matcher(text) find patterns in a text.
[/!]

What to do

Write the function server(port), which echoes every datagram that arrives on the given port to its sender, whole and unchanged. Listen carefully to what the clients say: the XMPP server only lets in the users that it knows, and Alice will give your account on this server as USER <name> and PASSWORD <secret> (letters and digits). Print the user name, then the password, each alone on a line, as soon as they come. Later, a message of Bob will give the port of the XMPP server as PORT <12345>: echo it as the others, then print the port alone on a line, close your socket and stop. Other messages may look like these ones: only their exact form counts, and the values differ from one world to the other. You will need all three in the next exercise.

Additional hints

  • Look at the trace: it tells where each of your datagrams went, and whether a socket waited for it there. Each client sends from its own machine and its own port: answer each datagram to the address of its own sender.

  • Bob checks that each of his lines comes back exactly as he sent it, and stops talking to a broken echo server. Look at the trace for the line that came back wrong. A datagram arrives whole, or not at all: if your buffer is shorter than the datagram, the rest of it is lost. The largest datagram that UDP carries over IPv4 has 65507 bytes.[!c] Send back the number of bytes returned by recvfrom(), not the length of a string: a datagram may hold a zero byte.[/!][!java|scala] receive() also shortens the length of the packet to the one of the datagram received: if you reuse the packet, the next datagrams are cut to this length. Create a new packet for each datagram.[/!]

  • Once Bob gave the port, nobody will talk to you anymore, or not in a way that matters: waiting for another datagram waits forever. Stop right after Bob's message.

  • Look for PORT <, then check that digits follow, up to the >. [!c]strstr() finds the text, and sscanf(found, "PORT <%d>", &port) returns 1 only if the number was read. The data of a datagram is not ended by a zero byte: add one after the bytes received (and keep room for it in your buffer).[/!][!python]re.search(rb"PORT <([0-9]+)>", data) finds it, and the group(1) of the match holds the digits, as bytes (decode() turns them into text).[/!][!java|scala] Pattern.compile("PORT <([0-9]+)>") finds it in the text of the datagram, and the group(1) of the matcher holds the digits, once find() returned true.[/!]

  • As for the port, but with letters and digits between the < and the >, both in a single message of Alice: look for each of them in every datagram. [!c]sscanf(found, "USER <%63[a-z0-9]>", user) reads at most 63 letters or digits into the array char user[64].[/!][!python]The pattern rb"USER <([0-9a-z]+)>" matches them.[/!][!java|scala]The pattern "USER <([0-9a-z]+)>" matches them.[/!]
