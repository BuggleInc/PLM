UDP client

So, Bob refused to speak over an open IRC channel and asked us to join on an XMPP server. But he only gave the text URL and not the IP address to which we should connect. The DNS (Domain Name System) is the way to go to convert such textual addresses to IP addresses, and this is usually done with a specific API. But Bob specified that we cannot use the usual network of DNS servers, because the address we are looking for is handled by a specific server that is not connected to the others. We have to talk to the BuggleInc DNS server directly by sending manual requests, rather than leveraging the usual DNS API. This poses an extra difficulty, as DNS servers use UDP rather than TCP as a transport protocol.

UDP is another way to send data over the Internet, much closer to the underlying network. It's not trying to mimic the file interface by connecting a local socket to the remote server, but rather lets you send packets directly. This exercise gives you the opportunity to learn about exchanging UDP packets as a client, while the next exercise lets you discover the server side of such communication before we can proceed to interact with the BuggleInc DNS server.

As with TCP, you have to open a socket before exchanging data. The difference is that no connection is required before exchanging data. You can use [!c|python]sendto[/!][!java|scala]send[/!] to send a packet to the peer specified in parameters, and [!c|python]recvfrom[/!][!java|scala]receive[/!] to receive data from any peer. The identity of the sending peer is indicated by this function. It is still possible to use connect in UDP, to specify a default [!c]struct sockaddr[/!][!python|java|scala]address[/!] to be used in each case, but it's an advanced feature that we won't use here.

[!c]

Here is the prototype of the main functions to send data over UDP. Check the manpages for more info.

  1. int socket(int domain, int type, int protocol): you want to use it with AF_INET, SOCK_DGRAM, 0 to get a UDP socket.
  2. ssize_t sendto(int sockfd, const void* buf, size_t len, int flags, const struct sockaddr *dest_addr, socklen_t addrlen) lets you send a packet to the specified peer. The data must be short enough to fit in a single UDP datagram (65507 bytes). If the data does not fit, sendto fails with the EMSGSIZE code.
  3. ssize_t recvfrom(int sockfd, void* buf, size_t len, int flags, struct sockaddr * src_addr, socklen_t * addrlen); blocks until the reception of the next datagram from the network. If src_addr is not NULL, the kernel fills it with the address of the sender (addrlen must then be a pointer to a variable that initially holds the size of the struct sockaddr passed as src_addr). If the provided buffer is too short to hold the data contained in the packet, any exceeding data is lost.

If you get a stack-buffer-overflow error from AddressSanitizer, it may be because you (or the recvfrom call) write after the end of the buffer.

[/!] [!python]

Here are the main methods of the socket module to exchange datagrams. Check its documentation for more info.

  1. socket.socket(socket.AF_INET, socket.SOCK_DGRAM) creates a UDP socket.
  2. sock.sendto(data, address) sends the bytes data in one datagram to address, a tuple (host, port). The data must be short enough to fit in a single UDP datagram (65507 bytes). If the data does not fit, sendto raises an OSError.
  3. sock.recvfrom(bufsize) blocks until the reception of the next datagram from the network, and returns a tuple of its data and of the address of the sender. If the datagram is longer than bufsize, any exceeding data is lost.
[/!] [!java|scala]

Here are the main classes of java.net to exchange datagrams[!scala], which Scala programs use[/!]. Check their documentation for more info.

  1. new DatagramSocket() creates a UDP socket.
  2. A DatagramPacket holds a datagram: its data in an array of bytes, the length of this data (getLength()), and the address of the other side. new DatagramPacket(byte[] buf, int length, InetAddress address, int port) prepares a datagram to send, where InetAddress.getByName(host) gives the address of a host. new DatagramPacket(byte[] buf, int length) prepares a datagram to receive, in the given array.
  3. socket.send(packet) sends the packet to its address. The data must be short enough to fit in a single UDP datagram (65507 bytes). If the data does not fit, send throws a SocketException.
  4. socket.receive(packet) blocks until the reception of the next datagram from the network, and puts it in the packet, with the address of its sender. If the array of the packet is too short to hold the data, any exceeding data is lost. The length of the packet becomes the one of the data received.
[/!]

What to do

Open a UDP socket, and send the content of the request parameter to the host:port specified by the parameters. Then, retrieve the packet that the server will send back and display its content on the standard output (with no additional new line nor anything) before closing the socket.
