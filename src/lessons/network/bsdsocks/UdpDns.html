DNS over UDP

Now that you know how to exchange datagrams, it is time to talk to the BuggleInc DNS server, which listens on the UDP port 53 of the machine 10.0.0.53. The URL given by Bob is not in the usual DNS: you have to talk to this server directly, by writing your queries yourself. Bob said to be careful: the DNS server may tell you more than what you ask, so pay attention to everything it sends back.

The DNS messages are binary: the numbers are written on several bytes, the most significant one first, and the names are not written as text. The world documentation (in the section The servers of this world) describes the format of the queries and of the answers, the kinds of records, and the meaning of the response codes. The trace of the world shows how the server understood each of your queries and what it answered, and explains why it rejects a malformed one.

[!c]

Here are the main tools to build and read binary messages in C.

  1. An array of unsigned char holds the bytes of a message. Use unsigned char rather than char, whose values above 127 are negative.
  2. uint16_t htons(uint16_t n) and uint16_t ntohs(uint16_t n) convert a number of 2 bytes between the byte order of your machine and the network byte order (htonl() and ntohl() do the same on 4 bytes). memcpy() copies such a number in the message, or out of it.
  3. sendto() sends exactly the number of bytes that you give, and recvfrom() returns the number of bytes received.
[/!] [!python]

Here are the main tools to build and read binary messages in Python.

  1. A message is a bytes value. bytes([3, 65]) builds bytes from their values, "text".encode("ascii") gives the bytes of a text, and + puts bytes one after the other. data[i] is the value of a byte, and data[i:j] the bytes from i to j (excluded).
  2. struct.pack("!HH", a, b) writes the numbers a and b on 2 bytes each, in network byte order ("!"). "I" stands for a number on 4 bytes. struct.unpack("!HH", data) reads them back, as a tuple.
[/!] [!java|scala]

Here are the main tools to build and read binary messages[!scala] in Scala, which uses the classes of Java[/!].

  1. A message is an array of byte. new ByteArrayOutputStream() collects bytes: write(b) adds one byte, writeBytes(array) adds an array, and toByteArray() gives the result. text.getBytes(StandardCharsets.US_ASCII) gives the bytes of a text.
  2. ByteBuffer.wrap(array) reads and writes numbers in an array, in network byte order: getShort(i) and putShort(i, n) on 2 bytes, getInt(i) and putInt(i, n) on 4 bytes, and get(i) for a single byte. The bytes of Java are signed: a byte above 127, such as c8 (200), reads as a negative number (-56), and b & 0xFF gives its value between 0 and 255.
[/!]

What to do

Find the IP address of the XMPP server hosting the chat room given by Bob, and print it on the standard output (such as 10.0.0.1, followed by a new line), before closing your socket. Your program must work in both worlds: the BuggleInc zone is not exactly the same in each of them. While exploring, you will certainly print what the server answers, but your output is compared to the expected one: in the end, print only the address, and remove your other messages.

The first step is certainly to ask the TXT records of the name buggleinc.lan, where the administrators of the zone leave notes, and to read all the records of the answer. They will probably give you more hints, and so may the TXT records coming in the additional section of the next answers. You don't even have to parse these answers to read their texts: click on your UDP socket to see a dump of all the data exchanged over it.

You still need to parse the final answer, though, as the target IP is not the same in all worlds of this exercise, so you cannot guess it. Parsing the answer is the only way to go.

Additional hints

Accessing a DNS server directly on the wire is not an easy task, but don't worry. This exercise provides several hints to help you in this task. Some of these hints are given below, while others come with the answers of the server.

  • The world's documentation describes each field (sections Header, Names and Question). Put together, the query for the TXT records of buggleinc.lan, with the ID 42, is made of these 31 bytes (in hexadecimal, the text between quotes standing for its ASCII bytes):

    00 2a  01 00  00 01  00 00  00 00  00 00     the header: ID 42, flags (only RD), 1 question, no other record
09 "buggleinc" 03 "lan" 00                   the name: each label preceded by its length, then a zero byte
00 10  00 01                                 the type TXT (16) and the class IN (1)

    Its answer is read as explained in the section Answers of this server of the documentation: skip the header and the question, then read the records one by one. Make sure to read every record, in particular the TXT records coming in the additional section of the answers to your next queries.

  • Here is the code sending the query for the TXT records of buggleinc.lan, with the ID 42:

    [!c]int sock = socket(AF_INET, SOCK_DGRAM, 0);
unsigned char query[] = {
  0x00, 0x2a, 0x01, 0x00, 0x00, 0x01, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00, /* the header */
  9, 'b', 'u', 'g', 'g', 'l', 'e', 'i', 'n', 'c', 3, 'l', 'a', 'n', 0,   /* the name */
  0x00, 0x10, 0x00, 0x01                                                 /* the type TXT and the class IN */
};
struct sockaddr_in server;
memset(&server, 0, sizeof server);
server.sin_family = AF_INET;
server.sin_port   = htons(53);
inet_pton(AF_INET, "10.0.0.53", &server.sin_addr);
sendto(sock, query, sizeof query, 0, (struct sockaddr*)&server, sizeof server);[/!]
[!python]sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
query = (struct.pack("!HHHHHH", 42, 0x0100, 1, 0, 0, 0)        # the header
         + bytes([9]) + b"buggleinc" + bytes([3]) + b"lan" + bytes([0])  # the name
         + struct.pack("!HH", 16, 1))                             # the type TXT and the class IN
sock.sendto(query, ("10.0.0.53", 53))[/!]
[!java]DatagramSocket socket = new DatagramSocket();
ByteArrayOutputStream query = new ByteArrayOutputStream();
query.writeBytes(new byte[] {0x00, 0x2a, 0x01, 0x00, 0x00, 0x01, 0x00, 0x00, 0x00, 0x00, 0x00, 0x00}); // the header
query.write(9);                                                    // the name, each label preceded by its length
query.writeBytes("buggleinc".getBytes(StandardCharsets.US_ASCII));
query.write(3);
query.writeBytes("lan".getBytes(StandardCharsets.US_ASCII));
query.write(0);                                                    // the zero byte ending the name
query.writeBytes(new byte[] {0x00, 0x10, 0x00, 0x01});             // the type TXT and the class IN
byte[] data = query.toByteArray();
socket.send(new DatagramPacket(data, data.length, InetAddress.getByName("10.0.0.53"), 53));[/!]

    Then receive the answer with [!c|python]recvfrom()[/!][!java|scala]socket.receive()[/!], in a buffer of 512 bytes, and read it as explained in the previous tip.

    [!c]

    For the next queries, you probably want a few helpers rather than writing each byte by hand: a buffer of unsigned char with the position of its next byte, and functions writing a byte, a number on 2 bytes (calling htons()), a label and a whole name, plus their counterparts reading an answer (calling ntohs() and ntohl()). The main risk is to get out of sync with the bytes of the answer, so check each step: print what you read on stderr, and remove these messages once your program works, as only the address must remain.

    [/!]

  • A SRV query is written as the TXT one: only the name and the type change. For example, the question of a SRV query on _imap._tcp.buggleinc.lan, the example name of the world's documentation, is:

    05 "_imap" 04 "_tcp" 09 "buggleinc" 03 "lan" 00     the name: the underscores are part of the labels
00 21  00 01                                       the type SRV (33) and the class IN (1)

    The documentation details a SRV record of an answer, field by field (section Answers of this server), and tells which target a client picks when there are several. Once you have the name of the target, a query of type A gives its address, which is what you print.

  • Print the flags of the answer in hexadecimal: an answer without error has the flags 85 00. If you get 0085, you read the two bytes in the wrong order[!c]: apply ntohs() to the number that you read[/!].

  • The world's documentation ends with a complete example of an A query and its answer, byte by byte: only the name changes. The data of the A record is the 4 bytes of the address, to print in decimal and separated by dots: 0a 00 00 2a is 10.0.0.42.
